# golang — generated Go clients

One package per `*_service.json` in this repository. The files are generated by
[`xbot-codegen`](https://github.com/xtech/xbot_framework/tree/main/xbot_service_interface_go/cmd/xbot-codegen)
from the schema next to them and checked in — do not edit them by hand.

The ids come from `service_ids.h`.

Each package composes the generic transport of the
[Go client](https://github.com/xtech/xbot_framework/tree/main/xbot_service_interface_go) — `xbot.Conn`
brings discovery, claim, RPC and DATA/configuration transactions — with the ids and typed calls of one
service: `ServiceID`, the `Fn*` constants, the enums of the schema, one method per RPC function, a
setter per register and a sender per input.

## Regenerating

You normally never run the generator: **CI regenerates the clients and commits the
result back to your branch**, then runs the tests on that regenerated tree. A schema
change is therefore a JSON-only edit, and no Go toolchain is needed to contribute one.

Two situations still need the generator from your side, because CI must not commit
there:

- a schema change that reaches the **default branch** without going through a PR
  branch (a protected branch cannot be pushed to by the workflow's token),
- a **pull request from a fork** (the token is read-only there).

The commit back needs a token that also triggers workflows, otherwise the bot commit
carries no check runs and a pull request with required status checks waits forever:
set a fine-grained personal access token (`contents: write`) as the `BOT_TOKEN`
secret. Without it the workflow falls back to `GITHUB_TOKEN` and warns.

```bash
go generate ./...    # uses the xbot_service_interface_go version from go.mod
```

If you do have Go installed, three local guards catch a stale client before you push:

- `go generate ./...` itself.
- `go test ./...` runs `TestGeneratedClientsAreUpToDate`, which regenerates every client
  in-process (via `codegen.Generate`) and names the first differing line - no
  `go generate`, no git, no network.
- the `go-generate-clients` hook in the repository root (`.pre-commit-config.yaml`)
  regenerates and refuses the commit until the clients are staged:
  `pipx install pre-commit && pre-commit install`. It saves the bot commit, nothing more.

Identifiers follow the Go naming rules for initialisms (`SoundId` -> `SoundID`, `PlayMp3` ->
`PlayMP3`), and every generated name that differs carries the `service.json` spelling in its doc or
trailing comment - so the schema stays the reference: `grep 'PlayMp3'` finds `PlayMP3`.

## Status

The schemas on this branch generate completely, with two exceptions that the generated files
comment on: **outputs** (DATA received from a service) need a receive loop in the Go client, so the
10 packages with outputs carry a note instead of callbacks.
